# paired-tags.nvim: автозакрытие и переименование тегов в Neovim

Плагин автоматически закрывает теги разметки и синхронизирует имена парных
тегов при редактировании в Neovim. Он использует Tree-sitter для HTML,
Django HTML-шаблонов, XML, JSX/TSX, Vue, Svelte и HTML внутри Markdown.
Также обрабатывает Enter между соседними HTML-тегами. [English README](README.md).

## Возможности

| Действие | Результат |
| --- | --- |
| Ввод `<section>` | Добавляет `</section>` и оставляет курсор между тегами. |
| Переименование любой стороны `<section>...</section>` | Обновляет имя соответствующего парного тега, в том числе при атрибутах и многострочном открывающем теге. |
| Enter в `<section>\|</section>` | Создаёт строку для содержимого с отступом; закрывающий тег остаётся на уровне открывающего. |

Поддерживаются `html`, `htmldjango`, `xml`, `javascriptreact`,
`typescriptreact`, `vue`, `svelte` и встроенный HTML в `markdown`.
Автозакрытие и переименование требуют работающего Tree-sitter-парсера текущего
языка. Плагин не устанавливает парсеры. Обработка Enter действует только в
`html` и `htmldjango`.

### Автозакрытие

- Закрывает завершённый открывающий тег: вложенные и пользовательские
  HTML-теги, JSX/TSX-компоненты, составные и пространственно-именованные имена,
  фрагменты JSX (`<>...</>`).
- Не дублирует имеющийся закрывающий тег и не добавляет его для
  самозакрывающихся и пустых HTML-элементов (`<br>`, `<img>` и другие).
  JSX/TSX-компонент `<Input>` не путается с HTML-элементом `<input>`.
- Учитывает `>` в кавычках атрибутов, JSX-выражениях и аргументах типов.
  Сравнения, строки, комментарии, код Markdown и другой текст вне разметки не
  превращаются в теги. При неоднозначном разборе плагин не забирает закрывающий
  тег родителя или соседнего элемента.

### Синхронное переименование

- Правка имени открывающего **или** закрывающего тега обновляет имя его пары.
  Работают ввод в Insert, команды Normal и вставка текста.
- Меняются только имена тегов: атрибуты, вложенное содержимое и другие элементы
  сохраняются. Учтены незавершённый ввод, одноимённые дочерние элементы,
  временно некорректная разметка, необязательные закрывающие HTML-теги,
  элементы с сырым текстом и многострочные атрибуты.
- Сохраняются регистр JSX-компонентов, регистр и UTF-8-имена XML-тегов.

### Enter между HTML-тегами

Один `<CR>` между соседними совпадающими тегами создаёт строку для содержимого.
Отступ берётся из действующих `shiftwidth`, `expandtab` и `tabstop`, поэтому
учитываются настройки проекта через EditorConfig. При несовпадении тегов,
открытом меню автодополнения, специальном буфере или другом типе файла Enter
остаётся обычным.

## Требования

- Проверена работа с Neovim 0.12.5. Более старые версии не проверены.
- Для автозакрытия и переименования установи нужные Tree-sitter-парсеры:
  `html`, `htmldjango`, `xml`, `javascript` для `javascriptreact`, `tsx` для
  `typescriptreact`, `vue`, `svelte`, `markdown` и `html` для встроенного HTML
  в Markdown. Установкой управляет твоя
  конфигурация Neovim. `nvim-treesitter` можно использовать для установки,
  но он не является обязательной зависимостью самого плагина.

Если парсера нет, автозакрытие и переименование не меняют буфер. Для
HTML Enter парсер не нужен.

## Установка

Через [lazy.nvim](https://github.com/folke/lazy.nvim):

```lua
{
  "hardcodd/paired-tags.nvim",
  main = "paired_tags",
  opts = {},
  lazy = false,
}
```

С другим менеджером плагинов добавь репозиторий в `runtimepath` и вызови:

```lua
require("paired_tags").setup()
```

`setup()` создаёт Insert-маппинги `>` и `<CR>`, обработчики изменения текста
и курсора, а также обёртку `vim.paste` для потоковой вставки. Повторный вызов
не дублирует их. Если другой плагин тоже управляет `<CR>`, отключи у него
замену этого маппинга; например, у `nvim-autopairs` используй
`map_cr = false`. Пользовательских опций пока нет.

## Ограничения и планы

PHP-шаблоны пока не поддерживаются. Подсветка текущей пары тегов ещё не
реализована. Обе задачи записаны в [ROADMAP.ru.md](ROADMAP.ru.md)
([English](ROADMAP.md)). При отсутствии парсера или безопасно определяемой
пары плагин пропускает изменение. Он не форматирует документ, не устанавливает
парсеры и не создаёт пары скобок или кавычек.

## Проверка

В репозитории есть отдельные тесты установки, Enter, парного редактирования,
56 языковых сценариев и четыре набора регрессий (51, 35, 62 и 188 случаев).
Запускай их из корня репозитория с установленными парсерами из списка выше.
`tests/bootstrap.lua` ищет их в стандартном каталоге данных Neovim; для
другого расположения укажи `PAIRED_TAGS_PARSER_RTP`.

```sh
nvim --headless -u NONE -i NONE -n \
  '+luafile tests/bootstrap.lua' \
  '+lua local ok, err = pcall(dofile, "tests/setup_spec.lua"); if not ok then print(err); vim.cmd("cquit") end' \
  +qa!

nvim --headless -u NONE -i NONE -n \
  '+luafile tests/bootstrap.lua' \
  '+luafile tests/tag_bug_report_4_spec.lua'
```

Аналогично запускаются `html_enter_spec.lua`, `paired_editing_spec.lua`,
`rename_fast_path_spec.lua`, `tag_scenarios_spec.lua`,
`tag_bug_regressions_spec.lua`, `tag_bug_report_2_spec.lua` и
`tag_bug_report_3_spec.lua`. Синхронным тестам
нужна показанная обёртка `pcall`/`cquit`; регрессионные раннеры завершаются
сами. Контракт и критерии приёмки: [SPECS.md](SPECS.md).
